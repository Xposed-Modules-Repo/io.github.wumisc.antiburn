## 探针给出了明确答案

v2.8.7 在 `handleLoadPackage` 第一行加了 `ENTER pkg=`，这次真机日志里它终于能说话了：

```
ENTER pkg=com.android.systemui      proc=com.android.systemui      ← 有
ENTER pkg=io.github.wumisc.antiburn proc=io.github.wumisc.antiburn ← 有（模块自身）
ENTER pkg=com.miui.contentcatcher   proc=io.github.wumisc.antiburn ← 有（小米内容捕获）
ENTER pkg=com.ss.android.ugc.aweme  …                              ← 没有
ENTER pkg=com.phoenix.read          …                              ← 没有
ENTER pkg=com.smile.gifmaker        …                              ← 没有
ENTER pkg=tv.danmaku.bili           …                              ← 没有
```

`ENTER` 打在 `VideoApps.of(pkg)` **之前**，走 `diagForce`，不受诊断开关、配置读取、周期相位任何影响。

它没出现，只有一种可能：**`handleLoadPackage` 没被调用**，即 LSPosed 没把模块加载进那四个进程。

## 所以「一版之间全散架」到底是怎么回事

| 环节 | 状态 | 依据 |
|---|---|---|
| 包名识别 | 正常 | 编译 `VideoApps` 实跑八个包名，全对 |
| 熔断器 | 正常 | 按 id 隔离 + 60 秒冷却，不会全停 |
| 配置读取 | 正常 | `status=true nav=true shift=true` |
| 代码崩溃 | 排除 | 崩了会先有 `ENTER` 再有 `INIT FAILED`，现在连 `ENTER` 都没有 |
| LSPosed 本体 | 正常 | SystemUI 注入了，自身进程也注入了 |
| **模块作用域** | **缺视频 App** | 唯一能解释「同样一份代码，systemui 进得去、抖音进不去」 |

`arrays.xml` 里的 `xposed_scope` 是**安装那一刻的一次性推荐值**，之后 LSPosed 不再同步。用户在管理器里改过、或管理器数据被重置过，就只剩 SystemUI。

## 前两版我查错了方向

日志连续出现：

```
LSPDB db=/data/adb/lspd/config/modules_config.db error=open:SQLiteException
```

v2.8.5 我以为是 SELinux 标签不对 → 改 `cp + chown + restorecon`。
v2.8.6 我以为是文件属主不对 → 改 `base64` 让应用自己创建文件。
**两次都还是同样的错。**

真因跟权限一点关系都没有：**LSPosed 的配置库是 WAL 模式，而 `SQLiteDatabase.OPEN_READONLY` 打开 WAL 库时必须先建 `<db>-shm` 共享内存索引，只读句柄建不了，SQLite 直接返回 `SQLITE_CANTOPEN(14)`**，Java 侧抛基类 `SQLiteException`。

改一行就好：`OPEN_READONLY` → `OPEN_READWRITE`（副本在应用私有目录，改的是副本，原库不受影响）。

这是我这两版的判断失误，与设备、与 ColorOS 都无关。

## v2.8.8 改了什么

1. **自检改 `OPEN_READWRITE`**，失败时删掉搬来的 WAL/SHM 再试一次。这是让作用域自检第一次真正能读出结果的修复。
2. **失败信息不再只有类名**：带上异常 `message` 与副本字节数（`:len=`），下次再读不出来能直接看出是文件为空、被截断还是 schema 不符。
3. **自检弹窗第一段就是注入证据**：
   ```
   注入证据（ENTER 命中的进程）：sysui,self
     → 四个视频 App 一个都没命中，模块代码从未进过这些进程。
       这不是定位算法的问题，是 LSPosed 没加载模块。
   ```
   命中目标包时显示 `OK:com.ss.android.ugc.aweme`。
4. **SELF 行加 `enter=`**：以后每次启动日志第一行就能判断注入通没通，不用再翻几百行。
5. **`app_overlay=1` 去掉**。这个字段此前读的是镜像文件里的历史值，而实际生效的 `ao=false`，两者自相矛盾，把排查带偏过一轮。现在恒 0。
6. **`hook=NONE` 文案改对**：不再说「由应用内区域兜底接管」——那条通道 v2.8.6 已经拆了。

## 装上之后

打开 App → 功能 → 通用 → **作用域自检**。三种结果对应三条路：

| 弹窗显示 | 含义 | 处理 |
|---|---|---|
| `✗ 抖音 com.ss.android.ugc.aweme` 若干行 | 作用域确实缺 | 照它列的勾上 → 保存 → **强行停止该 App 再打开** |
| `作用域已勾齐` 但仍无 `OK:` | 勾了却不注入 | 问题在 LSPosed 侧（框架版本 / Zygisk / 需重启手机），弹窗会附它自己的日志 |
| `读取失败：open:…:len=0` | 副本没拉到 | 把这一行发我，`:len=` 能直接定位是 su 没授权还是拉取被截断 |

## 一句话

代码这一侧已经只剩位置微移一条通道，它需要 LSPosed 真把模块送进目标进程。探针证明了这件事现在没发生 —— 先把作用域修好，再看定位准不准。在注入恢复之前，改任何定位算法都不会有反应。
