# v2.8.6：把盖黑彻底拆掉

## 结论

上一版不是「新通道还行」，是**旧通道根本没关掉**。日志自证：

```
MASK … fg=io.github.wumisc.antiburn … masking=true
     app=unknown appOn=true areas=---- rects=…应用内：x5(douyin RTBC)
```

前台已经是模块自己的设置页，五个抖音黑块还挂在上面。用户看到的就是「整个覆盖层糊在屏幕上」。

## 为什么 v2.8.4 的「强制关闭」没生效

`Cfg.appAreaOn` 的字段默认值是 `true`，而 `config()` 里只有**读到 `enable_app_overlay` 这个键**才把它置成 `false`：

```java
} else if ("enable_app_overlay".equals(k)) {
    c.appAreaOn = false;
}
```

镜像文件里缺这个键时，这个分支根本不执行，默认值 `true` 原样留下。v2.8.4 只改了「读到 =1 时不生效」，没改「读不到时是什么」，所以盖黑一直在跑。

同时 `MaskView` 在「无可画区域」时只调 `setMasked(false)`，字段里的五个矩形没清，下一次 `setMasked(true)` 会原样复活 —— 这就是切走以后黑块还留在屏幕上的原因。

## 这一版怎么改

1. **编译期常量总闸**：`private static final boolean APP_AREA_CHANNEL = false;`，`appRects()` 第一行就判它。配置、镜像、Provider、旧文件全都绕不过去。
2. **默认值改 false**，`config()` 读完再无条件 `c.appAreaOn = false;`，两层保险。
3. **清残留矩形**：无可画区域时 `setRects(null, null, emptyList())`，不只 `setMasked(false)`。
4. **写盘恒 0**：`lines["enable_app_overlay"] = "0"`，旧配置里的 `=1` 会被覆盖。
5. **删掉「预览 5 秒」**：那个按钮就是强制画一帧黑块，点一下满屏黑。
6. **UI 状态默认 false**：`AbState` 与 `AbStateSaver`（索引 38 / 39）都改成 false，Bundle 恢复路径不会再把通道带回 true。

## 顺手修的作用域自检

v2.8.5 用 `cp + chown + restorecon` 把 `modules_config.db` 搬进私有目录，真机上 `SQLiteDatabase.openDatabase` 直接抛 `SQLiteException`：

```
LSPDB db=/data/adb/lspd/config/modules_config.db error=open:SQLiteException
```

属主改了，SELinux 标签没落到 `app_data_file`，进程照样读不了。现在改成 root 端只做 `base64 -w0` 输出，**文件由应用进程自己创建**，标签和 uid 天然正确；WAL / SHM 一并搬，SQLite 打开时自动重放。

## 现在的状态，说清楚

这一版之后，App 内**只剩位置微移**一条通道，它需要 LSPosed 真的把模块注入目标进程。

日志里 `inject=douyin:0 drama:0 kuaishou:0 bilibili:0` 说明注入没通，所以**装上这一版在抖音里仍然看不到效果**——但至少屏幕上不会再出现黑块。

下一步只有一件事：功能 → 通用 → 作用域自检，看它列出缺哪几个包。自检现在能真正读库了。
