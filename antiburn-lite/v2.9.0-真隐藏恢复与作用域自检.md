# v2.9.0：原因查清了，隐藏方式也改回来了

## 一、到底是为什么

这次日志里有一条关键新行，把整条链断在了哪里彻底说清了：

```
LSPDB db=/data/adb/lspd/config/modules_config.db
      error=open:SQLiteException:no such column: mid (code 1 SQLITE_ERROR):,
      while compiling: select mid from modules wher :len=364544
```

这句话同时证明了两件事：

1. **配置库这次真的打开了**（`len=364544`，364 KB，正常大小）—— v2.8.8 把 `OPEN_READONLY` 改成 `OPEN_READWRITE` 修对了。WAL 库用只读句柄必然 `CANTOPEN`，前两版往 SELinux、属主、chcon 上查，方向从一开始就错了。
2. **但 SQL 写错了列名**。新版 LSPosed 的 `modules` 表以 `module_pkg_name` 为主键，根本没有自增的 `mid`。所以自检喊了四版「读不出来」，真相是「能读，只是问错了问题」。

而自检读不出来的这四版里，每版都在改看得见的那一层（定位算法、微移幅度、盖黑通道）—— **这些代码在四个视频 App 里一行都没执行过**。

```
SELF ver=2.8.8 inject=douyin:0 drama:0 kuaishou:0 bilibili:0
     enter=self,sysui,sys
```

`enter=` 是 `handleLoadPackage` 的第一行，只有 SystemUI、模块自身、小米内容捕获三个进程命中。四个视频 App 一个都没有 → 模块代码从未进过这些进程 → 改什么都等于没改。

## 二、为什么感觉「还不如之前」

把时间线摊开就清楚了：

| 阶段 | 用户看到的效果 | 实际生效的通道 |
|---|---|---|
| v2.7.x | 状态栏、导航栏真的会消失 | SystemUI 注入正常 |
| v2.8.2–2.8.3 | 视频 App 里出现黑块（部分区域） | **无障碍 / SystemUI 覆盖层**在冒充，不是真隐藏 |
| v2.8.6 起 | 什么都没有 | 覆盖层按你的要求拆了，只剩微移，而微移要注入 |

也就是说：视频 App 内那块「以前能用」的效果，从来不是注入路径给的，是盖黑层按屏幕比例画出来的。这恰好解释了历史上的怪现象——「只有右侧生效」「底部生效一次」「点了没用」：那是比例蒙对了一部分。

拆掉盖黑之后，唯一剩下的通道就是注入，而注入没通。所以主观感受是越来越差，实际上是**原来那个「像能用」的假象被拿掉了**。

## 三、这一版做了什么

### 1. 自检终于能读出作用域（关键）

不再假设 `mid` 存在，改成按 `pragma table_info` 现查真实表结构：

- `modules` 表 → 挑出存包名的那一列（`module_pkg_name` / `pkg_name` / 含 `pkg` 的列）
- `scope` 表 → 优先按 `module_pkg_name=?` 关联（新版），没有这一列才退回 `mid=?`（旧版）
- 两种都对不上时，把**真实列名**写进错误信息（`schema:scope(a,b,c)`），下一版据此适配，不再靠猜

装上去点「功能 › 通用 › 作用域自检」，它会第一次真正告诉你：**LSPosed 里勾了哪几个、设备上装了哪几个、缺哪几个**。

### 2. 按你的要求改回周期性真隐藏

- `hideSafe()` 从 `shiftDeep`（平移 2~3px）改回 `transparentDeep`（`alpha=0` + `INVISIBLE`）——像素直接不发光，防烧屏强度比微移高一个量级
- 恢复「隐藏 N 秒 → 显示 M 秒」的相位循环，时长仍读你的「周期时长」设置（默认 40 / 10）
- tick 间隔从 2 秒收紧到 1 秒，避免周期调短后切换迟滞
- 左滑引导条一并走真隐藏

### 3. 针对你说的「容易产生 bug」加了一道保险

真隐藏最怕的就是识别错了把内容区一起藏掉，屏幕发黑。所以 `hideSafe()` 里加了**面积保险**：

```java
// 宽、高都超过屏幕 45% 的 View 不是控件，是内容容器 / 播放器
return v.getWidth() > sw * 0.45f && v.getHeight() > sh * 0.45f;
```

命中就不藏，只把可能残留的旧偏移归零。宽高**双**超限才拦，底部整条导航（宽 100%、高 8%）不会被误伤。

### 4. 文案修正

`SCOPE` 行不再说「开启无障碍服务使用应用内区域兜底」—— 那条通道 v2.8.6 已经拆了，留着只会把人往错的方向带。

## 四、必须先说清的一件事

**这一版在抖音里大概率仍然看不到效果**，因为注入还没通。改回真隐藏、加面积保险，都是「等注入恢复后立刻生效」的准备动作，不是当场就能看见的变化。

真正要让功能动起来，只有一步：**功能 › 通用 › 作用域自检**。

| 弹窗显示 | 含义 | 处理 |
|---|---|---|
| `✗ 抖音 com.ss.android.ugc.aweme` 若干行 | 作用域确实缺 | 照它列的勾上 → 保存 → **强行停止该 App 再打开** |
| `已勾选作用域：0 个` | 一个都没勾 | 同上，全部勾上 |
| `作用域已勾齐` 但仍无 `OK:` | 勾了却不注入 | 问题在 LSPosed 侧（框架版本 / Zygisk / 需重启手机） |
| `读取失败：schema:scope(...)` | 表结构与预期不同 | 把这行发我，列名已在里面，一次就能改对 |

自检结果现在是可信的——库能打开、列名现查。以前那句「读不出来」不再成立。
