# v2.8.5 说明：先把「有没有注入」变成可见，再用反编译结果修 B站定位

## 一、这轮真机日志说明了什么

日志里同时存在这两类行：

```
INJECTED SystemUI process=com.android.systemui
SELF ver=2.8.4 inject=douyin:0 drama:0 kuaishou:0 bilibili:0 hookdiag:0 ... hook=NONE
LSPDB /data/adb/lspd/config/modules_config.db sqlite3=missing
```

- `INJECTED SystemUI` 有 → 模块本体正常，LSPosed 在跑，SystemUI 作用域是通的。
- `inject=douyin:0 drama:0 kuaishou:0 bilibili:0`、`hookdiag:0`、没有任何 `HOOK-ATTACH`
  → **四个视频 App 的进程里，模块一行代码都没执行过。**

`INJECTED <app>` 是 `XposedInit.handleLoadPackage` 的第一行，走 `diagForce`，不受「诊断日志」开关影响，
也不受配置链路影响。它没出现，只可能是 LSPosed 根本没把模块加载进那个进程。

结论：**「功能区整体不能用」不是定位不准，是没注入。** 没有注入，`DouyinHook`
的 R/T/B/C 扫描、位置微移都跑不到；v2.8.4 又把盖黑通道关掉了，于是表现成「一点反应都没有」。

另一个被忽略的事实：`sqlite3=missing`。v2.8.4 的作用域自检是用 `sqlite3` 命令行读
`modules_config.db`，而绝大多数 Android 设备不带这个二进制。所以这道自检从上线起
**一次都没成功过**，作用域里到底有没有那四个包，日志里从来没有答案。

## 二、反编译四款 App 的实证结果

四份官方/商店版 APK（应用宝与 B站官方直链，2026-11 抓取）：

| App | 包名 | 版本 | 资源 id 名 | 能否靠 id 定位 |
|---|---|---|---|---|
| 抖音 | com.ss.android.ugc.aweme | 41.1.0 | 47044 个，全部被重命名成 `_` / `0` / `00` / `00a` | 不能 |
| 红果短剧 | com.phoenix.read | 7.4.5.32 | 16520 个，全部是 `a` / `a_` / `a0` / `a00` | 不能 |
| 快手 | com.smile.gifmaker | 14.10.20 | 仅 761 个，且集中在直播相关；主界面底部导航 id 已被抹掉 | 基本不能 |
| 哔哩哔哩 | tv.danmaku.bili | 8.91.1 | 22789 个，**语义完整**（`bottom_navigation` / `app_bar` / `nav_top_bar`） | 能 |

也就是说：过去所有「按资源 id 精准定位」的设想，对抖音、红果、快手都不成立 ——
它们的 id 名是混淆产物，这次叫 `a0`，下次可能叫 `b7`，跟着混淆结果走等于没锚点。
只有 B站 保留了可读的资源名。

> 附带结论：B站 APK 的**资源文件路径**被混淆（`res/LBY.xml`、`res/6R5.xml`），
> 但 `resources.arsc` 里的资源**名字**没混淆，所以「按名字取 id」这条路线对 B站 有效。

## 三、B站：按真实布局结构做锚点

把 `layout/bili_app_activity_main_v2` 反编译出来（真实文件 `res/LBY.xml`），只有 5 个节点，
内容全部由 Fragment 动态填充；底部导航与顶部栏在另一份布局 `res/6R5.xml` 里，实际结构是：

```
androidx.coordinatorlayout.widget.CoordinatorLayout   id=coordinatorLayout
├─ FrameLayout                                        id=main_top_layout
│    └─ ImageView                                     id=main_top_bg
├─ FrameLayout                                        id=content
├─ com.bilibili.lib.homepage.widget.TabHost            id=bottom_navigation   ← 底部 5 个 tab
│      layout_gravity=bottom, height=wrap_content, minHeight=@dimen/…
└─ tv.danmaku.bili.ui.main2.widget.HomeAppBarLayout    id=app_bar            ← 顶部整块
      └─ androidx.appcompat.widget.Toolbar             id=nav_top_bar        ← 顶部搜索栏
```

`TabHost` 是自绘 ViewGroup，子节点不是 `ImageView`，宽度也不一定贴满；
`HomeAppBarLayout` 由 `AppBarLayout` 的 behavior 托管、位置随滚动变化。
这两个都过不了旧版 `collectBottom` / `scoreTop` 的几何门槛 —— 真机表现正是
「B站只有右侧按钮列生效，顶部标题和底部导航都不动」。

v2.8.5 的改法（`DouyinHook.rescan`）：

1. 先跑原有几何扫描，结果不动；
2. 若当前是 B站 进程，按**名字**取 `bottom_navigation` / `app_bar` / `nav_top_bar`；
3. 取到且可见、尺寸有效 → 用 id 结果**覆盖**几何结果；取不到 → 原样走几何兜底。

按名字而不是按数值：`bottom_navigation` 在 8.91.1 里是 `0x7f090681`，下个版本必然变；
名字不变。`getIdentifier` 首次解析后进 `ConcurrentHashMap` 缓存，不增加扫描开销。

抖音 / 红果 / 快手 不开这条路径 —— 它们的资源名是混淆产物，按名字查等于撞运气。

## 四、作用域自检：不再依赖 sqlite3

`LspScope` 重写为：

1. `su` 把 `modules_config.db`（连同 `-wal` / `-shm`）复制到应用私有目录，属主改回自身 uid；
2. 用系统自带的 `android.database.sqlite.SQLiteDatabase` 只读打开；
3. 查 `modules` 表拿本模块的 `mid`，查 `scope` 表拿已勾选包名；
4. 用 `PackageManager`（失败再退 `pm list packages`）列出设备上**真实安装**的四个目标包，
   与之做**精确**比对（不做前缀匹配 —— LSPosed 的注入判定就是精确包名）；
5. 输出一行结论：`LSPDB mid=… scope=N[…] installed=N[…] missing=N[…]`。

写入一律不做。LSPosed 服务端在启动时把作用域读进内存、与 WAL 共用同一份文件，
外部 INSERT 要同时处理属主、SELinux、WAL 一致性，还可能让管理器判定配置损坏；
在管理器里勾选只需几步，风险却全在用户设备上，不值得代劳。

设置页「功能 → 通用 → 作用域自检」直接弹窗显示：

- 配置库路径、模块是否登记、已勾选了哪些包；
- 设备上找到的目标应用，逐个标 ✓ / ✗；
- 缺几个、下一步该做什么；
- 一个「打开 LSPosed」按钮，直接跳到管理器，省掉自己找图标。

## 五、看到自检结果后怎么做

1. 弹窗里出现 `✗ 抖音 com.ss.android.ugc.aweme` 这类行 → 就是它没被注入；
2. 点「打开 LSPosed」→ 模块 → 抗烧屏 → 作用域 → 勾上所有 `✗` 的应用 → 保存；
3. **强行停止**对应 App（或在最近任务里划掉），再重新打开；
4. 日志出现 `INJECTED Douyin` / `HOOK-ATTACH pkg=…` 才算真正进去了。

如果自检显示 `scope=complete`、`missing=0`，但日志里仍然没有 `INJECTED`，
那就不是作用域的事，需要看 LSPosed 自身的日志（管理器 → 日志），
把「模块加载失败 / 跳过某个包」那几行发出来。

## 六、这一版改了什么

- 新增：`LspScope` 只读作用域自检（SQLiteDatabase 实现，不再依赖 sqlite3）
- 新增：「功能 → 通用 → 作用域自检」入口 + 结果弹窗 + 跳转 LSPosed
- 修复：B站 主界面底部导航（TabHost）与顶部栏（HomeAppBarLayout）改用资源 id 锚点定位
- 文案：删掉「未注入时由无障碍按屏幕比例遮盖」这类已经不成立的承诺
- 版本：2.8.5 / versionCode 48
