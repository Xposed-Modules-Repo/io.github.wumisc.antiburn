# v2.8.7：把「为什么全散架」这件事查到底

## 先说已经排除的

| 怀疑对象 | 验证方式 | 结论 |
|---|---|---|
| 包名识别写错 | 实测 `VideoApps.of()` 八个包名 | 全部正确：`com.ss.android.ugc.aweme` → DOUYIN |
| 功能熔断器全局拉闸 | 读 `FeatureGuard` 实现 | 按 id 隔离 + 60s 冷却，不会一处失败全停 |
| 配置读错 / 主开关关着 | 日志 `status=true nav=true shift=true` | 主开关正常 |
| 盖黑盖住了画面 | 日志 `appOn=true rects=x3(douyin RTB-)` | 确实在盖，但那是另一个 bug（v2.8.6 已硬关） |

## 剩下的唯一解释

`handleLoadPackage` 没有在抖音进程里被执行。

代码上只要这个方法被调用，`INJECTED Douyin` 就一定会打出来：它在 `else if (kind == DOUYIN)` 分支第一行，走 `diagForce`，不受诊断开关、配置读取、周期相位任何影响。而 v2.8.0 起它前面只有一句 `VideoApps.of(pkg)`，这一句已实测正确。

所以：**模块没被 LSPosed 加载进那四个进程。**

## 为什么是「一版之间」

时间线上唯一同时影响全部四个目标 App 的改动，是 v2.8.0 把 `arrays.xml` 的 `xposed_scope` 从 6 项扩到 13 项。

LSPosed 的「作用域」是它自己数据库里的勾选记录，`arrays.xml` 只是推荐值。模块更新、声明变化时，LSPosed 会重新比对这份声明；而 SystemUI 是从 v2.6.x 起唯一一直在清单里、从未变过的一项 —— 这也正是日志里只有它还在被注入的原因。

这是**推断**，不是确证。确证要靠下面这个探针。

## v2.8.7 加了什么

**1. 入口探针（关键）**

```java
public void handleLoadPackage(XC_LoadPackage.LoadPackageParam lpparam) {
    diagForce("ENTER pkg=" + pkg + " proc=" + proc);   // 第一行，不依赖任何业务类
    VideoApps.Kind kind = VideoApps.of(pkg);
```

它把「日志里什么都没有」这个二义性彻底消掉：

| 日志表现 | 含义 | 处理方向 |
|---|---|---|
| 有 `ENTER pkg=com.ss.android.ugc.aweme` + `INJECTED Douyin` | 正常注入 | 功能应当生效，若无效再查定位 |
| 有 `ENTER pkg=…` 但无 `INJECTED` | 进来了，中途崩了 | 查 `INIT FAILED`，是代码 bug |
| 连 `ENTER` 都没有 | LSPosed 没加载模块 | 作用域 / 框架侧，改代码无用 |

**2. 自检回读 LSPosed 自己的日志**

作用域勾齐却仍无 `INJECTED`，问题就在框架侧（版本与新系统不兼容、Zygisk 未生效、dex 加载失败）。这些只有 LSPosed 自己的日志写得清楚，现在自检把 `/data/adb/lspd/log/modules.log` 里与本模块相关的最近 10 行直接读出来显示。

## 装上后怎么用

1. 打开抖音刷 10 秒，再回到本应用导出日志
2. 搜 `ENTER pkg=`
   - 有 `com.ss.android.ugc.aweme` → 说明注入是通的，问题在别处，把日志发我
   - 没有 → 进「功能 → 通用 → 作用域自检」，看缺哪几个包，以及下面附的 LSPosed 日志
